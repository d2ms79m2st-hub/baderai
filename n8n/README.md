# n8n — مساعد بدر

لم تُنشأ Workflows إنتاجية في هذه النسخة لأن حساب n8n وWebhook ورمز المصادقة غير متاحة. هذا الملف يحدد العقد المطلوبة قبل التفعيل ولا يعتبر التكامل منفذًا.

## Human handoff

- **المحفز:** `POST /webhook/bader/human-handoff` بعد تسجيل طلب تدخل بشري.
- **المدخل:** `{ "sessionKey": "...", "summary": "...", "createdAt": "..." }`.
- **التحقق:** HTTPS، رمز سري في ترويسة، منع التكرار بواسطة `sessionKey` ووقت الإنشاء.
- **الإجراءات:** إنشاء تذكرة، إرسال ملخص مختصر للقناة الإدارية المعتمدة، إعادة الحالة إلى التطبيق.
- **المخرج:** `{ "accepted": true, "ticketId": "...", "status": "pending" }`.

## Catalog sync

- **المحفز:** جدولة يحددها مالك المتجر أو Webhook من المصدر الرسمي.
- **التحقق:** المصدر مصرح به، الحقول الأساسية مكتملة، السعر والمخزون قابلان للتحقق، وسجل المصدر ووقت المزامنة محفوظان.
- **الإجراء:** إدخال نسخة مراجعة، ثم اعتمادها يدويًا قبل ظهورها للعميل.
- **الفشل:** لا يتم استبدال البيانات السابقة؛ يسجل الخطأ ويرسل تنبيهًا غير حساس.

## Failed workflow alert

- **المحفز:** فشل أي Workflow مهم.
- **الإجراء:** إرسال نوع الفشل ومعرف التنفيذ والوقت، دون بيانات العميل أو قيم الأسرار.
- **إعادة التشغيل:** يدويًا بعد مراجعة السبب، مع idempotency للعمليات الحساسة.

## بيانات الاعتماد المطلوبة

تضاف داخل Credentials في n8n أو مدير أسرار مناسب، لا داخل العقد أو مستودع GitHub: عنوان التطبيق، رمز Webhook، قناة Telegram أو البريد إن اعتمدت، وبيانات المصدر الرسمي المسموح بها. يجب اختبار كل Workflow في بيئة اختبار أولًا وتوثيق نتيجة الاختبار قبل عرضه على أنه جاهز.
