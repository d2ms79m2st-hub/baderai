# خطة تطبيق migration على الإنتاج

## الحالة

هذه خطة تنفيذ فقط. لم تُطبق migration على `baderai-auth`، ولا ينبغي تطبيقها دون موافقة صريحة على الإجراء المحدد أدناه.

## المشروع المستهدف

- مشروع Supabase: `baderai-auth`
- project ref: `ukbukoagjlddtevdxyzc`
- migration: `20261025001000_create_catalog_tables.sql`

## ما سيتغير عند الموافقة

سيتم إنشاء جداول الكتالوج الخمسة وسياساتها وفهارسها ومنحها الصريح. لن يتغير مصدر الكتالوج في الواجهة، ولن تُنشأ جداول السلة أو الطلبات أو الدفع أو الشحن، ولن تُعدل Auth أو `private.is_admin()`.

## فحوصات ما قبل التنفيذ

1. تأكيد أن الجداول الخمسة غير موجودة في الإنتاج.
2. أخذ نسخة احتياطية أو تأكيد وجود نقطة استرجاع مناسبة.
3. مراجعة migration والـ rollback من commit `11c741a` وما بعده.
4. تطبيق migration باسم `create_catalog_tables` على project ref الإنتاجي.
5. فحص الجداول وRLS والسياسات والفهارس بعد التطبيق.
6. إبقاء الواجهة على ملفات الكتالوج الحالية إلى أن يُنفذ ترحيل البيانات ومقارنة كاملة في مرحلة لاحقة.

## التراجع

الـ rollback يحذف سياسات الترحيل ثم الجداول الخمسة. تشغيله بعد إدخال بيانات الكتالوج يحذف تلك البيانات ولا يعيدها، لذلك يحتاج موافقة مستقلة ونسخة احتياطية.
