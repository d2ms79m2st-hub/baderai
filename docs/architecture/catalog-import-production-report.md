التاريخ: 2026-10-25

## المصدر ونطاق العملية

تمت مطابقة `client/src/data/catalog.ts` مع `client/src/data/bader-official-catalog.json` قبل الاستيراد. كلاهما يمثل 73 منتجًا، مع 10 تصنيفات و118 علاقة تصنيف و73 صورة أساسية و73 لقطة سعر. استُخدمت لقطة الكتالوج الرسمية المثبتة على commit `dae830a`، وليس مخزونًا مباشرًا من Salla.

بصمة الملف المحلي:

```text
8e421b5f50f3fd00425da2a419a08709d8433411b5d8fdd29bbaf74c783681ce
```

تحققَت قاعدة البيانات من البصمة نفسها قبل الاستيراد عبر المصدر المثبت، لذلك لم تُقبل لقطة مختلفة أو ملف متبدل.

## ما تم إدخاله

تم الإدخال إلى جداول الكتالوج الموجودة فقط:

- `catalog_products`: 73
- `catalog_categories`: 10
- `catalog_product_categories`: 118
- `catalog_product_prices`: 73
- `catalog_product_images`: 73

استُخدمت المعرفات الأصلية للمنتجات والتصنيفات. العملة `SAR` محفوظة، والأسعار الثلاثة (`price`, `regular_price`, `sale_price`) محفوظة كلقطة ملاحظة، مع `observed_at = 2026-10-22T05:38:41Z`. لم تُعامل `available` أو `out_of_stock` كمخزون مباشر.

الاستيراد قابل لإعادة التشغيل: المنتجات والتصنيفات والعلاقات والأسعار تستخدم مفاتيحها الطبيعية مع `ON CONFLICT`; الصور لا تُكرر عند وجود المنتج والرابط واللقطة نفسها. لا توجد عمليات حذف.

## اكتشاف وتصحيح مهم

المصدر لا يرسل `rating` كرقم دائمًا. توجد 70 قيمة `null` وثلاثة كائنات JSON مثل:

```json
{"count": 2, "stars": 5}
```

فشلت المحاولة الأولى قبل إدخال السجلات الجديدة عند اكتشاف هذا التعارض، ولم يتم إسقاط هذه البيانات. تم تعديل المخطط إلى `jsonb` عبر migration تصحيحية، مع قيد يقبل `null` أو كائن JSON، ثم أُعيد الاستيراد بنجاح. يوجد rollback واقٍ يرفض التحويل الرقمي إذا كان سيؤدي إلى فقدان كائنات التقييم.

## ما لم يتغير

- لم يتغير مصدر الكتالوج في الواجهة.
- لم تُحذف منتجات أو جداول أو بيانات قائمة.
- لم تُشغّل أي عملية rollback على الإنتاج.
- لم تُنشأ جداول السلة أو الطلبات أو الدفع أو الشحن.
- لم تُعدّل Auth أو `private.is_admin()`.
- لم تُنشأ تكلفة مدفوعة.

## المحاولات الفاشلة وكيف عولجت

1. وُجد خطأ timestamp في مولد SQL المحلي (`Z+00:00`) قبل التنفيذ، ولم تُرسل تلك الدفعة.
2. بعد الدفعة التجريبية الناجحة، رفض الاستيراد الكامل أولًا نوع `rating` الرقمي؛ اكتُشف أن المصدر يستخدم كائن JSON. بقيت الدفعة التجريبية فقط (`1/2/2/1/1`) ولم تُضف سجلات جزئية من المحاولة الفاشلة.
3. بعد تعديل نوع `rating`، فشل تحقق داخلي بسبب تعارض اسم alias مع متغير PL/pgSQL؛ تراجعت محاولة الاستيراد الجديدة، ثم نجحت المحاولة المصححة.
