# خطة التفعيل التدريجي لمصدر كتالوج Supabase

## الوضع الحالي

المتجر الأساسي (`#/store`) يقرأ من المصدر المحلي افتراضيًا لأن `VITE_CATALOG_SOURCE` غير مضبوط. صفحة الاختبار `#/store-supabase` تقرأ عبر عميل Supabase publishable وتُظهر ما تسمح به RLS العامة.

## التفعيل التجريبي

لتجربة المصدر الجديد في build منفصل، اضبط:

```text
VITE_CATALOG_SOURCE=supabase
```

عندها يقرأ المتجر الأساسي من Supabase بعد التحميل، ويعرض حالات التحميل والخطأ والبيانات الفارغة. عند فشل الاتصال، يستخدم snapshot المحلي كـfallback مع تنبيه صريح بأنه قديم وليس مخزونًا مباشرًا.

القيمة الافتراضية لأي قيمة أخرى، أو غياب المتغير، هي `local`.

## التراجع

للتراجع، أزل `VITE_CATALOG_SOURCE` أو اضبطه إلى:

```text
VITE_CATALOG_SOURCE=local
```

ثم أعد build والنشر. لا يحتاج التراجع إلى تعديل قاعدة البيانات أو RLS أو المصادقة. GitHub Pages الحالي لا يضبط المتغير، لذلك بقي المتجر المنشور افتراضيًا محليًا أثناء هذه المرحلة.

## حدود البيانات

القراءة العامة تستخدم RLS الحالية؛ لذلك لا تعرض المنتجات النافدة. حالات `available` و`out_of_stock` هي حالة snapshot وليست مخزونًا لحظيًا. لا يحتوي هذا المسار على كتابة أو لوحة إدارة أو تغيير أسعار.
