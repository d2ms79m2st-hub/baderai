# تدقيق ربط كتالوج Supabase والتفعيل التدريجي

التاريخ: 2026-10-25

## القرار

لم يُفعّل Supabase كمصدر افتراضي للمتجر المنشور. القيمة الافتراضية لـ`VITE_CATALOG_SOURCE` هي `local`، ولا توجد قيمة تفعيل في إعدادات GitHub Actions الحالية.

أصبح التفعيل الاختياري جاهزًا عبر:

```text
VITE_CATALOG_SOURCE=supabase
```

ويمكن التراجع منه بإزالة المتغير أو ضبطه إلى `local`. لا يحتاج التراجع إلى تعديل قاعدة البيانات أو RLS أو المصادقة.

## اختبار القراءة العامة الفعلي

نُفّذ الاستعلام في مشروع الإنتاج بدور `anon`:

- المنتجات المرئية: 67
- الأسعار المرئية: 67
- الصور المرئية: 67
- علاقات التصنيف المرئية: 108
- المنتجات النافدة المكشوفة: 0

الفرق بين إجمالي العلاقات 118 والمرئي منها 108 متوقع بسبب حجب العلاقات المرتبطة بالمنتجات النافدة عبر RLS.

## تطابق البيانات

- `rating = null`: 70
- `rating` ككائن JSON: 3
- حالات التوفر غير الصالحة (`available=true` و`out_of_stock=true`): 0
- العملة والأسعار والصور والتصنيفات تُحوّل إلى واجهة `CatalogProduct` الحالية.
- الصور الحالية تُرتب حسب `sort_order`، ولا تُستخدم الصور غير الحالية.
- المنتجات ذات الأسعار أو الصور أو التقييمات الناقصة لا تحصل على قيم مخترعة؛ تُستخدم `null` أو قائمة فارغة أو رابط صورة فارغ كما يفرض النوع الحالي.

## حالات الواجهة

تمت مراجعة صفحة `#/store-supabase` المنشورة فعليًا؛ عرضت 67 منتجًا ووسمت المصدر `Supabase public RLS`.

تم إصلاح fallback كان يعيّن snapshot المحلي لكنه لا يعرض بطاقاته بسبب شرط عرض خاطئ. أصبح يعرض البطاقات المحلية مع رسالة صريحة بأنها snapshot قديمة وليست مخزونًا مباشرًا، مع زر إعادة المحاولة.

المتجر الأساسي لا يزال محليًا ما لم يُضبط flag التفعيل. عند التفعيل، توجد حالات تحميل وفشل واتصال دون بيانات، وfallback محلي واضح.
