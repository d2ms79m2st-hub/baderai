# تشغيل مصادقة Bader AI

## الحالة الحالية

المشروع يحتوي على خادم Express/tRPC ومصادقة Manus OAuth وجلسات JWT موقعة ومخطط Drizzle/MySQL. النشر الحالي على GitHub Pages ثابت، لذلك لا يستضيف `/api/oauth/callback` أو `/api/trpc` ولا يمكنه تنفيذ مصادقة حقيقية بمفرده.

تمت إضافة دعم CORS مقيد في الخادم. لا يُسمح بطلبات المتصفح من Origins خارج القائمة المحددة في `BADER_ALLOWED_ORIGINS`. الجلسة تستخدم `HttpOnly`, `Secure`, و`SameSite=None` لتعمل مع واجهة منشورة على نطاق منفصل.

## إعدادات الخادم السرية

ضع القيم في مدير أسرار الاستضافة الخادمية فقط، وليس في GitHub أو ملفات الواجهة:

- `MANUS_PROJECT_ID`: معرّف مشروع Manus الذي ينتمي إليه التطبيق. مصدره إعدادات مشروع Manus.
- `MANUS_OAUTH_API_URL`: عنوان API الرسمي لخدمة Manus OAuth المستخدمة من الخادم لتبادل رمز OAuth وجلب بيانات المستخدم.
- `MANUS_OAUTH_PORTAL_URL`: عنوان بوابة تسجيل الدخول العامة. القيمة المعتادة `https://manus.im` إذا لم يزود Manus المشروع بعنوان مختلف.
- `MANUS_JWT_SECRET`: قيمة عشوائية طويلة خاصة بالخادم لتوقيع جلسات المستخدم. تُنشأ داخل مدير أسرار الاستضافة ولا تُشارك.
- `DATABASE_URL`: رابط MySQL الخاص ببيئة الإنتاج. يجب أن يكون من قاعدة موثوقة مع نسخ احتياطي.
- `BADER_ALLOWED_ORIGINS`: قائمة Origins مفصولة بفواصل، مثل `https://d2ms79m2st-hub.github.io`. لا تضع مسارًا أو شرطة مائلة أخيرة.
- `BADER_BACKEND_URL`: النطاق العام HTTPS لخدمة API نفسها، مثل `https://baderai-api.example`. يستخدمه الخادم لبناء callback OAuth؛ لا تضع هنا رابط GitHub Pages.
- `BADER_FRONTEND_URL`: أصل الواجهة المنشورة، مثل `https://d2ms79m2st-hub.github.io/baderai`، لعودة المستخدم بعد نجاح OAuth.

القيمة الاختيارية `OWNER_OPEN_ID` لا تمنح صلاحية مدير تلقائيًا؛ الصلاحيات تُحسم من حقل `role` في قاعدة البيانات عبر الخادم.

## إعدادات OAuth

يجب تسجيل callback الخادمي التالي لدى إعداد Manus OAuth:

```text
https://<backend-domain>/api/oauth/callback
```

ويجب أن يكون `redirectUri` الذي ترسله الواجهة هو نفس العنوان حرفيًا. لا تستخدم رابط GitHub Pages كـ callback؛ GitHub Pages لا يملك مسار API.

## مسار النشر المقترح

المسار الأنسب للكود الحالي هو نشر خادم Node/Express وقاعدة MySQL على خدمة تدعم الاثنين، مع إبقاء GitHub Pages للواجهة مؤقتًا. Railway هو البديل العملي إذا لم يتوفر مشروع WebDev مُدار؛ وثائق Railway الرسمية تدعم نشر Express من GitHub أو Dockerfile، وتوفر قالب MySQL ومتغيرات اتصال مثل `MYSQL_URL`.

بعد إنشاء النطاق الخادمي، تُضبط متغيرات الخادم السابقة، ثم يُربط عميل الواجهة بعنوان API الخادمي بدل `/api/trpc` النسبي. لا يعتبر النظام جاهزًا قبل اختبار callback، `auth.me`، إعادة التحميل، و`auth.logout` من نطاق الواجهة المنشور.

## ما لم يُنفذ بعد

لم تُنشر خدمة خادمية من هذه البيئة لأن مشروع WebDev غير مربوط، ولا توجد بيانات قاعدة أو أسرار OAuth متاحة. لذلك لم يتم تغيير رابط GitHub Pages أو الادعاء بنجاح تسجيل الدخول.
