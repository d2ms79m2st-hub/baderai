# مصادقة Bader AI

## التنفيذ الحالي

واجهة Bader AI المنشورة على GitHub Pages تستخدم مشروع Supabase قائمًا باسم `baderai-auth` لمصادقة البريد الإلكتروني وكلمة المرور. يشمل المسار إنشاء الحساب، تسجيل الدخول، تسجيل الخروج، استمرار الجلسة، استعادة كلمة المرور عبر البريد، وتعيين كلمة مرور جديدة من رابط الاستعادة.

تظل بنية Express/tRPC وManus OAuth الموجودة في المستودع محفوظة للتوافق مع الخدمات الخادمية السابقة، لكن الواجهة الثابتة تستخدم Supabase Auth لأن GitHub Pages لا يشغّل `/api/oauth/callback` أو `/api/trpc`.

## الأمان

- لا تُستخدم كلمات المرور داخل كود Bader AI أو قاعدة بيانات التطبيق؛ يديرها Supabase Auth.
- الجلسات تُحفظ وتُحدّث تلقائيًا عبر عميل Supabase الرسمي.
- مفتاح `sb_publishable_...` هو مفتاح publishable مخصص للمتصفح، وليس service-role key ولا يمنح صلاحيات إدارية.
- جداول `profiles` و`chat_messages` و`human_requests` محمية بـ RLS، وسياسات المستخدم مقيدة بـ `auth.uid()`.
- لا توجد مفاتيح إدارية أو كلمات مرور أو `DATABASE_URL` داخل الواجهة أو Git.

## إعدادات النشر

الإعدادات العامة الاختيارية موجودة في `.env.example`:

- `VITE_SUPABASE_URL`
- `VITE_SUPABASE_PUBLISHABLE_KEY`

ويوجد fallback عام للمشروع الحالي داخل عميل الواجهة حتى يعمل بناء GitHub Pages الحالي دون إعداد أسرار. يمكن استبدالهما بمتغيرات بيئة في سير العمل من دون تغيير الكود.

## إعداد Supabase المطلوب

يجب أن يكون عنوان الموقع في Supabase هو:

```text
https://d2ms79m2st-hub.github.io/baderai/
```

ويجب إضافة العنوان نفسه ضمن Redirect URLs المسموح بها. عند تشغيل تأكيد البريد، يرسل Supabase رابط التحقق إلى هذا العنوان. لا تستخدم service-role key في GitHub Actions أو الواجهة.

## التحقق المنفذ

- `pnpm check` يمر بنجاح.
- `pnpm test` يمر بنجاح: 12 اختبارًا.
- `pnpm build:static` يمر بنجاح.
- نقطة Supabase الحية تستجيب، وتسجيل الدخول ببيانات غير صحيحة يُرفض بـ `invalid_credentials`، وطلب الاستعادة العام يعيد استجابة ناجحة دون كشف وجود البريد.

لم يُنشأ حساب اختبار دائم أو تُرسل كلمة مرور حقيقية من هذه البيئة؛ لذلك لا يُقدّم هذا التوثيق ادعاءً بنجاح تسجيل دخول حساب مستخدم حقيقي قبل أن ينشئ مالك الموقع حسابه ويتحقق من بريده.
